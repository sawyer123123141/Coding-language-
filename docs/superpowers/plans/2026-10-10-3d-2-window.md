# 3D plan 2: textures, sprites, bulk rectangles and draw3d

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** the window side of the spec. That is textures and sprites in `draw`, a bulk `draw.rects`, the new `draw3d` module (a camera, `MeshData` turned into GPU meshes, cubes, spheres and lines), `window.ticks_usec`, paths relative to the program's folder, and the particles demo re-measured with `draw.rects`.

**Architecture:**
- **Built-in modules.** `draw.kes` gains `Rect`, `Texture` and the texture natives; a new `draw3d.kes` (which uses `draw`) holds `Camera`, `MeshData` (Kestrel code), `Mesh` and its natives.
- **Natives** live in `kestrel-window` (`kestrel/window/src`), as `kestrel_<module>_<name>`, using plan 1's ABI (arrays and struct results). They fail with `kestrel_runtime::panic::fail_at_call`, which appends "on line N".
- **GPU objects:**
  - `gpu.rs` keeps a per-window registry from handle id to the raylib object (a texture, or a mesh's parts).
  - Ids come from a process-wide counter starting at 1.
  - Drops arrive through the runtime hook `kestrel_runtime::gpu::set_drop_hook`, set at `window.open`. The hook only pushes the id onto a mutex-guarded queue, because it runs on any thread.
  - `window.frame()` drains the queue and unloads; closing the window unloads everything.
- **The 2D/3D switch:** `pass.rs` tracks whether drawing is in 2D or in 3D with the camera. Every `draw.*` native enters 2D first, and every `draw3d.*` drawing native enters 3D (an error with no camera yet). `window.frame()` and `window.screenshot` end a 3D pass. The same state machine runs in headless mode, so the camera error appears there too; only the raylib calls are skipped.
- **raylib:**
  - `rmodels.c` is compiled now, and JPG loading is on.
  - Meshes go through `UploadMesh`/`DrawMesh` with the default material. Mesh draws cull raylib's front faces, because Kestrel's clockwise fronts are OpenGL's back faces.
  - `draw.rects` fills one dynamic mesh's vertex buffer and draws it once.
- **Paths:** `paths.rs` resolves a relative path against the program's folder. The CLI sets it for `kestrel run`; a built exe uses its own folder.

**Tech Stack:** Rust workspace `kestrel/` (window crate on vendored raylib 6.0 built with `cc`, hand-written `extern "C"` declarations in `window/src/raylib.rs`), program tests under the JIT and as an exe, a real-window GPU smoke test.

**Spec:** `docs/superpowers/specs/2026-10-10-3d-textures-design.md`. Read "What it looks like", "`draw`: textures, sprites and bulk rectangles", "`draw3d`", "`window`: a precise clock and paths", "GPU objects" and "How it's built" first. Plan 1 (`docs/superpowers/plans/2026-10-10-3d-1-compiler.md`, done) built the compiler pieces this plan uses.

## Review Focus

1. **GPU objects made and dropped every frame** (a `let t = draw.make_texture(...)` inside the frame loop) must not pile up. The queue drains every frame, so the number of live objects stays flat. Task 1 tests this with a unit test, and Task 2 with a headless program run for many frames that checks the live count.
2. **Mixed 2D, 3D and 2D in one frame, and the next frame:** the camera persists, a new frame starts in 2D, and the order on screen is the order of the calls. Task 5's smoke case draws a 2D rectangle over a 3D quad and checks the second frame too.
3. **Objects after the window closes,** and drops from `par for` threads. A drop after close is ignored, and drawing after close is the existing error. A drop from another thread is queued and freed at the next frame. Task 1 has unit tests for these.
4. **Empty inputs:**
   - an empty `MeshData` (an all-air chunk) makes a mesh that draws nothing;
   - `draw.rects` with an empty array or list draws nothing;
   - `make_texture` with no pixels is an error.
   Tasks 2, 3 and 5 test these.
5. **Relative paths** when the program runs from another working directory, and from a built exe in another folder. Task 1 unit-tests the resolution. Task 2's `textures.kes` proves both end to end: the harness runs `kestrel run` from the CLI crate's folder while the program sits in `tests/programs`, and the exe run has its asset copied next to the exe.

```rust
/// What a handle stands for. Headless objects keep only what natives check.
pub enum Object {
    Texture { texture: Option<rl::Texture>, width: i32, height: i32 },
    Mesh { parts: Vec<rl::Mesh>, has_uvs: bool, vertex_count: i32, triangle_count: i32 },
}
/// Adds an object made on the window's thread; gives its new id (1, 2, 3, ... for the whole process).
pub fn add(object: Object) -> i64;
/// Runs `f` on the object `id` stands for, or gives `None` (id 0, or an object already freed).
pub fn with<T>(id: i64, f: impl FnOnce(&Object) -> T) -> Option<T>;
/// The runtime's drop hook: queues `id`. Safe on any thread; never touches the GPU.
pub fn queue_drop(id: i64);
/// On the window's thread: frees every queued object (unloading it from raylib when `real`).
pub fn drain(real: bool);
/// When the window closes: frees every object (raylib unloads only when `real`, before `CloseWindow`), then forgets them.
pub fn close_all(real: bool);
/// How many objects are alive on this thread (tests).
pub fn live() -> usize;
```

  - The registry is `thread_local!` (the window's thread). The queue is a `static Mutex<Vec<i64>>`, and the id counter a `static AtomicI64`.
  - Freeing a texture is `UnloadTexture`. Freeing a mesh is `UnloadMesh` for each part, after nulling the CPU pointers raylib would otherwise `free` (see Task 5).
  - Task 1 only stores and frees `Object`s; Tasks 2 and 5 make them.
  - `kestrel_window_open` calls `kestrel_runtime::gpu::set_drop_hook(gpu::queue_drop)`. The first hook set stays, and it is always this one.
- `paths.rs`:

```rust
/// Sets the folder relative paths are read from: the program's own folder under `kestrel run`.
/// The first call wins. A relative `dir` is made absolute against the current directory.
pub fn set_program_dir(dir: &Path);
/// `path` (UTF-8 bytes from Kestrel) as a file to read or write: an absolute path as given; a
/// relative one inside the program's folder, else the running executable's folder.
pub fn resolve(path: &[u8]) -> PathBuf;
```

- `window.ticks_usec() -> i64` (`kestrel_window_ticks_usec`): microseconds since `window.open`.
  - Real: `((GetTime() - time_base) * 1_000_000.0) as i64`.
  - Headless: `frames * 1_000_000 / 60` (integer division), where `frames` is the count `window.time()` uses.
  - After close it keeps its last value, like the other queries.
  - It prints no headless line.
- `// asset: <file>` in a program test: before running the exe, the harness copies `tests/programs/<file>` to `<exe folder>/<file>`, creating folders. Under the JIT the program runs from `tests/programs` and finds the file in place. The directive also counts as a known one in `expectations`.

// A rectangle: its top-left corner and its size (Godot's Rect2).
pub struct Rect {
    pos: vec2
    size: vec2
}

// A texture on the GPU. It is freed when the value that holds it goes away.
pub struct Texture {
    id: GpuHandle
    width: int
    height: int
}

pub native load_texture(path: string) -> Texture
pub native make_texture(width: int, height: int, pixels: [Color]) -> Texture
pub native texture(tex: Texture, pos: vec2, tint: Color)
pub native texture_rect(tex: Texture, pos: vec2, size: vec2, tint: Color)
pub native texture_region(tex: Texture, region: Rect, pos: vec2, size: vec2, tint: Color)
```

  - ABI, in `abi.rs`:
    - `#[repr(C)] struct KTexture { id: i64, width: i32, height: i32 }` (16 bytes);
    - `#[repr(C)] struct KRect { pos: V2, size: V2 }`;
    - `#[repr(C)] struct KSeq { ptr: *const u8, len: i64 }` (the first 16 bytes of an array or list header), with `unsafe fn elems<T>(s: *const KSeq) -> &[T]` that gives an empty slice for a null `ptr` or `len <= 0`.
    - A `Texture` result is written through the pointer passed first.
- **Behaviour** (spec "`draw`: textures, sprites and bulk rectangles"):
  - **`load_texture`:**
    - `paths::resolve` the path.
    - If the file doesn't exist: "draw.load_texture couldn't read {path} (looked for {resolved}): no such file".
    - Otherwise `LoadImage`. If that gives no data: "... : it isn't a PNG, JPG or BMP image".
    - Then the real backend runs `LoadTextureFromImage`, `SetTextureFilter(TEXTURE_FILTER_POINT)` and `SetTextureWrap(TEXTURE_WRAP_REPEAT)`, then `UnloadImage`.
    - Headless reads the image the same way (CPU only, for its size and errors) and stores an `Object::Texture { texture: None, .. }`.
    - Print `{path}` as written and `{resolved}` with forward slashes.
  - **`make_texture`:**
    - Errors: "draw.make_texture needs a width and height above 0, not {w} by {h}" and "draw.make_texture needs width × height pixels: {w} by {h} is {w*h}, not {len}". Use the `×` character, as the spec does.
    - The pixels are converted with `KColor::to_raylib` into RGBA8 rows from the top-left, as an `Image` (`PIXELFORMAT_UNCOMPRESSED_R8G8B8A8` = 7, 1 mipmap) loaded with `LoadTextureFromImage`. The image memory is Rust's and is freed by Rust.
  - **Drawing:**
    - Every drawing native first gets the object with `gpu::with`. Id 0 gives "draw.texture got an empty texture; make one with draw.load_texture or draw.make_texture" (with the calling native's name).
    - Real drawing is `DrawTexturePro(texture, source, dest, Vector2 {0, 0}, 0.0, tint)`:
      - `texture`: source = the whole texture, dest = `pos` and the natural size.
      - `texture_rect`: dest = `pos`/`size`.
      - `texture_region`: source = `region`.
    - **Negative sizes:** a negative `size` covers the rectangle it spans from `pos` (dest x becomes `pos.x + size.x`, width `-size.x`) and mirrors the image. Mirroring is a negative source width or height, which raylib flips. A negative `region` size mirrors too, and the two mirrorings cancel when both are negative. Keep this in a small pure function, `fn place(pos, size, region) -> (rl::Rectangle, rl::Rectangle)`, and unit-test it.
  - **Headless lines,** for example `draw.texture Texture(id: 1, width: 4, height: 4) vec2(x: 10, y: 40) Color(r: 1, g: 1, b: 1, a: 1)` and `draw.load_texture "assets/checker.png"`. `make_texture` prints `draw.make_texture 4 4 16` (width, height, pixel count). A `Rect` prints `Rect(pos: vec2(...), size: vec2(...))`.

**Interfaces:**
- Produces: `pub native rects(positions: [vec2], size: vec2, color: Color)` in `draw.kes` (`kestrel_draw_rects(positions: *const KSeq, size: *const V2, c: *const KColor)`). It draws exactly what calling `draw.rect(p, size, color)` for each `p` in order would. A `list[vec2]` argument works (plan 1).
- **Negative sizes:** `rect`, `rect_outline` and `rects` with a negative width or height cover the rectangle the size spans from `pos`. Use one shared `fn span(pos: V2, size: V2) -> (V2, V2)` (top-left and positive size).
- **Headless:** `draw.rects 3 vec2(x: 2, y: 2) Color(r: 1, g: 0, b: 0, a: 1)`. The positions print as their count.
- **Real drawing (`bulk.rs`):**
  - One dynamic raylib `Mesh` per window (thread-local), uploaded with `UploadMesh(&mut mesh, true)`. Its capacity doubles when a call needs more rectangles: re-upload with the new size and unload the old one.
  - Each call writes 6 vertices per rectangle (two triangles, positions as `x, y, depth`) into a reused `Vec<f32>`, updates the vertex buffer with `UpdateMeshBuffer(mesh, 0, ...)`, sets the mesh's `vertexCount` to `6 * n` and `triangleCount` to `2 * n` for the draw, and calls `DrawMesh` with the default material. The material's diffuse colour is `color`, the transform is the identity, and vertex colours are left white.
  - Before drawing, flush raylib's batch (`rlDrawRenderBatchActive`) so earlier shapes stay underneath.
  - Turn backface culling off around the draw (`rlDisableBackfaceCulling`, then `rlEnableBackfaceCulling`), so winding never matters.
  - Use a z inside the 2D projection's range. raylib's own 2D vertices sit at the batch's current depth, starting at -1 and rising by 1/20000 per draw call (`rlgl.h` `currentDepth`). Copy what makes a pixel show in the smoke test, and say what you chose in a comment.
  - An empty array draws nothing and touches no GPU state.
  - Free the mesh and material at window close (`gpu::close_all` time, or the pass/close hook Task 1 added).
- **Fallback:** if `DrawMesh` in 2D can't be made to draw correctly, fill raylib's own batch with `rlBegin(RL_TRIANGLES)` / `rlColor4ub` / `rlVertex2f` in one loop. Record it in the report with the measured cost, because it is the slow path the spec wanted to skip.

```
pub struct MeshData {
    vertices: list[vec3] = []
    colors: list[Color] = []
    uvs: list[vec2] = []
    indices: list[int] = []

    // Four corners, clockwise seen from the front (as in Godot), as the
    // triangles a b c and a c d. Adds no uvs.
    pure quad(var self, a: vec3, b: vec3, c: vec3, d: vec3, color: Color) {
        let base = self.vertices.len
        self.vertices.add(a)
        self.vertices.add(b)
        self.vertices.add(c)
        self.vertices.add(d)
        for k from 0 to 4 {
            self.colors.add(color)
        }
        self.indices.add(base)
        self.indices.add(base + 1)
        self.indices.add(base + 2)
        self.indices.add(base)
        self.indices.add(base + 2)
        self.indices.add(base + 3)
    }

    // One triangle, clockwise seen from the front. Adds no uvs.
    pure triangle(var self, a: vec3, b: vec3, c: vec3, color: Color) {
        let base = self.vertices.len
        self.vertices.add(a)
        self.vertices.add(b)
        self.vertices.add(c)
        for k from 0 to 3 {
            self.colors.add(color)
        }
        self.indices.add(base)
        self.indices.add(base + 1)
        self.indices.add(base + 2)
    }
}

- **`make_mesh` (real):**
  - An empty `MeshData` (0 vertices) makes a mesh with no parts, which draws nothing.
  - Otherwise, for each part (one part, with no split, when unindexed or at most 65,536 vertices), build a raylib `Mesh`:
    - `vertexCount`, `triangleCount`;
    - `vertices`, `texcoords` (or null), `colors` (or null), and `indices` (or null when unindexed);
    - pointers into Rust `Vec`s gathered for the part. When there is one part and no split, point `vertices` and `texcoords` straight at the list memory (no copy).
  - Call `UploadMesh(&mut mesh, false)`. Then set every CPU data pointer in the `Mesh` to null, because the GPU has the data and raylib's `UnloadMesh` would `free` pointers it doesn't own. Store the parts in `gpu::Object::Mesh`.
  - The result is `Mesh { id, vertex_count, triangle_count }`, with the counts of the whole `MeshData`.
  - Headless stores the counts and `has_uvs` only.
- **`mesh` and `mesh_textured`:**
  - `enter_3d`, then flush the batch, then `rlSetCullFace(RL_CULL_FACE_FRONT)` (Kestrel's clockwise fronts are OpenGL's back faces).
  - For each part, `DrawMesh(part, material, translate(pos))`. The material is the window's default one (`LoadMaterialDefault`, made once per window), with `maps[MATERIAL_MAP_DIFFUSE].color = tint`, and for `mesh_textured` with `.texture` set to the texture (put the default texture back after).
  - Then `rlSetCullFace(RL_CULL_FACE_BACK)`.
  - `translate` is a `Matrix` with `m0 = m5 = m10 = m15 = 1` and `m12, m13, m14 = pos`. Note the field order in `raylib.h`.
