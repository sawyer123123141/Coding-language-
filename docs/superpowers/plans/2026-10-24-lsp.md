# The language server and the cost lens (2026-10-24)

The user rated Kestrel's tooling 4/10: no editor support. The plan agreed that day: generics proposal (main session, in parallel), this language server and cost lens, then generics, then a voxel engine. Built in the worktree branch `claude/kestrel-lsp-068145`, not pushed and not merged: the main session reviews and merges.

## What was built

**`kestrel-lsp`** (`kestrel/lsp`, a new crate in the workspace), a language server over standard input and output, on rust-analyzer's synchronous `lsp-server` 0.7 and `lsp-types` 0.95:
- **Diagnostics as you type**, from the real parser, linker and checker (`kestrel_driver::analyze`), with the same stages as `kestrel check` (a parse error stops before linking, a link error before checking). Modules are found as the compiler finds them (`m.kes` next to the file, the built-in `window`, `draw`, `draw3d`, `input`), and an open module's unsaved buffer is read in place of the file on disk. A diagnostic in a module shows in the module's file; a file used by several open programs shows each diagnostic once. The help line follows the message.
- **Positions in UTF-16 units** (`lsp/src/pos.rs`): spans are bytes, LSP columns are UTF-16 code units (`é` 1, `🦅` 2); tested with non-ASCII lines, a position inside a surrogate pair, CRLF line ends and positions past the end.
- **Hover**: a local (`var total: int`, `let s: Hit.Struck`), a parameter, a constant, a function or method's signature (`pure Point.len(self) -> float`, `geom.area(w: int, h: int) -> int`), a struct with its fields, an enum with its variants, an interface with its methods, a field (`Point.x: float`), a variant (`Hit.Struck(damage: int)`), a `match` arm's variant, a type in an annotation, a name in a `use` line, and any other expression's type. It works with check errors elsewhere in the file (the checker's tables are kept), and while the file doesn't parse it answers from the last version that did, with offsets moved past the edit.
- **Go to definition**: functions, methods (also through an interface), structs, enums, variants, fields (also a variant's), locals, parameters, constants, `remove b`'s item, items imported from another module file (`geom.area`, `use { scale from geom }`, the module name itself), and the built-in modules (their source is written once to `%TEMP%/kestrel-lsp/builtin/` so the editor can open it; the server doesn't check those copies).
- **`@prove` errors and the "`@assume` removes no check" warnings**, as `kestrel check` gives them, on open and save (they need the program lowered).
- **The cost lens** (milestone 2), on open and save, switchable: for each line of the file, what `kestrel check --report` says about it (each check left, allocation, other way to fail and call not inlined, with the report's reason text, and "range analysis stopped early" on a function's line). Shown as an inlay hint at the end of the line (default), or as Information diagnostics (source `kestrel cost`), or both; the line's hover lists it all ("**Cost** (at the last save)"). When the report's reason has a plain shape the lens adds the change that removes it: `@assume(k >= 0 and k < xs.len)` for a bounds check on a named index (tested: after it is added and saved, the check is gone), `@assume(b != 0)` for a division by a name, and `+%`/`-%`/`*%` for an integer overflow that may be meant to wrap. Settings: `costLens.enabled`, `costLens.build` (`checked` or `release`), `costLens.show` (`hints`, `diagnostics`, `both`); the server asks the editor to fetch hints again after each lowering.
- A compiler panic while analysing becomes one error on the file ("internal compiler error: ..."), and the server keeps running.

**The VS Code extension** (`kestrel/editors/vscode`): a TextMate grammar (keywords, `@prove(...)` with its contract names, `@assume(...)` with the expression inside, hex/float/integer numbers with `_`, strings with escapes and `"{interp}"` interpolation holding Kestrel code, `//` comments, types, declarations, calls, the wrapping operators), a language configuration (brackets, `//` comments, auto-closing, indentation on `{`), and a plain-JavaScript client on `vscode-languageclient` 9 that starts `kestrel-lsp` (the setting `kestrel.server.path`, else `PATH`, else the repository's `target/release` then `target/debug`) and passes the settings. Install steps are in the README ("Editor") and the extension's README: build the server, `npm install`, `vsce package`, `code --install-extension`.

**Small compiler APIs** (no change to what is checked or compiled):
- `kestrel_check::check_keeping_tables`: `check_with` without dropping the tables when there are errors (`check_with` now calls it).
- `kestrel_driver::analyze` and `Analysis` (`driver/src/analysis.rs`): load, link and check with a reader for module files, returning the sources, each file's `use` lines (linking drops them), the linked program, the tables and the diagnostics with their spans.
- `kestrel_driver::compile_as_reading` and the type `Read`: `compile_as` with a reader (the driver's `load` takes the reader; `compile_as` passes the disk's). `Source` (was the private `File`) is public, and `Compiled::sources()` returns it.
- `kestrel_driver::Proved::diags`: `prove`'s diagnostics with their spans, beside the rendered text.
- `kestrel_kir::range::render::label` is public (the report's item labels).

## Rulings

- **R1. A separate crate and binary, `kestrel-lsp`, not a `kestrel lsp` subcommand.** It keeps `lsp-server`, `lsp-types`, `serde` and `url` out of the compiler binary, and the server needs neither codegen nor the runtime staticlib that `kestrel-cli`'s build script makes, so it builds in a fraction of the time. *If wrong:* a subcommand is a few lines in `cli/src/main.rs` calling `kestrel_lsp::serve_stdio`.
- **R2. Synchronous `lsp-server` + `lsp-types` 0.95** (0.95 uses `url::Url`, whose file-path conversion is reliable on Windows; 0.97 moved to `fluent_uri`). One thread, a 256 MiB stack like `kestrel`'s.
- **R3. Edits are analysed when no message is waiting, or before the next request.** A burst of keystrokes is analysed once, and a request always sees the latest text. Every open document is analysed again on any change, since one may use another; checking is fast enough (no lowering).
- **R4. Full-text sync.** Simpler than incremental edits, and Kestrel files are small.
- **R5. Each open file is the entry file of its own program.** Hover and definition in a file use that file's analysis. A file with `pub` items and no `main` is checked as a module (`needs_main` false), so a module open on its own gets no "program needs a `main()` function" error. *If wrong:* a module without `pub` items, or a program with a `pub` item and no `main` yet, is checked the other way.
- **R6. Diagnostics follow `kestrel check`'s stages exactly**; only navigation keeps the checker's tables when there are errors (`check_keeping_tables`). Nothing is lowered from tables with errors.
- **R7. Lowering (contracts, assumption warnings, the cost lens) runs on open and save only**, as the task asked: it compiles the program. Until the next save its findings follow edits line by line (`lsp/src/shift.rs`: lines above and below an edit keep theirs, moved; the edited lines lose theirs); when the check has errors they are dropped, and a file opened or saved with errors is lowered as soon as they are fixed.
- **R8. The lens shows each item on its own file's line**, once per line however many times it was inlined; items of inlined code from another file show in that file when it is open.
- **R9. Inlay hints by default** (they read like a lens and stay out of the Problems list); Information diagnostics on request.
- **R10. The lens's suggestions are made by the server from the report's text** (the report itself suggests nothing): only for shapes where the change is plain and the `@assume` reads the same names. They are advice, worded "if `k` is always inside `xs`", since an `@assume` is checked in checked builds and trusted under `--release`.
- **R11. Built-in modules open from a temp copy** (`%TEMP%/kestrel-lsp/builtin/<name>.kes`), not checked by the server.
- **R12. The extension is plain JavaScript**, with no build step; only `npm install` for `vscode-languageclient`.

## Tests

- `lsp/src/pos.rs`: offsets and UTF-16 positions round-trip, non-ASCII columns, a position inside a surrogate pair, CRLF and clamping. `lsp/src/diagnostics.rs`: a diagnostic's range and help. `lsp/src/nav.rs`: offsets moved past an edit. `lsp/src/shift.rs`: lines moved past an edit. `lsp/src/config.rs`, `lsp/src/lens.rs` (the suggestions), `lsp/src/work.rs` (which files are modules).
- `lsp/tests/nav.rs` (9 tests): hover and definition on a two-file program held in memory: locals, interpolated strings, loop variables, functions and built-ins, structs, fields, methods, enums, variants, `match` arms and bindings, constants, items of the other module (all three ways), `use` lines, types, and hover with a check error elsewhere.
- `lsp/tests/stdio.rs` (4 tests): the real binary over standard input and output with real LSP messages: initialize; diagnostics in the program's file and the module's file, at UTF-16 columns after `é🦅`; the module's unsaved buffer read instead of the disk; an edit clearing the error; hover and definition into the module; hover while the file doesn't parse; the cost lens on open (hints, Information diagnostics, hover, the suggested `@assume`), after save with the `@assume` added (the check is gone), and switched off through `workspace/didChangeConfiguration`; definition into a built-in module; the lens waiting for a clean check after opening with an error, then following a line added above; shutdown and exit.
- `kestrel-driver`'s unit tests: four for `analyze`.
- The grammar was checked with `vscode-textmate` on a sample (comments, `@prove`/`@assume`, hex, interpolation, declarations); the extension was packaged with `vsce` (462 KB). It was not run inside VS Code (that opens a window).

## Not done

- Completion, rename, find references, signature help, document symbols, formatting, semantic tokens, and a code action that inserts the lens's `@assume`.
- An edited line loses its lens items until the next save (they aren't recomputed while typing).
- The extension isn't published, and it wasn't exercised in a running VS Code.
- The generics round will change the checker: `resolve.rs` reads the tables' `res`, `bind_local`, `field_index`, `match_arms`, `removes`, `call_local` and the `*_by_name` maps, and `find.rs` walks every node of the AST, so a new node kind needs a line there.

## Review

A Sonnet review of the whole branch (read-only) found no panics, no span underflows and no change to the driver's behaviour, and seven state defects, all fixed in the review commit: a panic while lowering left an analysis of the old text (now the analysis is stored before lowering, and lowering has its own `catch_unwind`); a file opened with an error was never lowered after the fix until a save; the lens and the lowered diagnostics stayed on their old lines while editing (now moved, R7); the hints outlived the lowered diagnostics after an error; a line map was rebuilt per diagnostic; `exit` without `shutdown` was ignored; a node with an empty default span matched at offset 0.
