# The I/O Round Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `to_bytes`/`from_bytes[T]`/`first_difference` as built-ins; the `file`, `time`, `args` and `env` built-in modules; `kestrel run --record` and `kestrel replay`; Pong's replay on disk and the voxel engine's save.

**Architecture:**
- **Built-ins** follow `checksum`: the checker judges the type with `kestrel_check::snapshot`, KIR generates one helper function per type (`kir/src/lower/helpers.rs` caches), codegen only gains two runtime calls for string bytes. The type fingerprint is a compile-time constant.
- **Modules** are embedded `.kes` files with bodyless `native` declarations (`driver/std/`), implemented as `#[no_mangle] extern "C"` functions in a new `kestrel-runtime` module tree (`runtime/src/natives/`), found by the JIT through a new `kestrel_runtime::native_symbols()` and by exes in either staticlib. Natives gain string, list and optional results (by the existing `out` pointer).
- **Record and replay** live in the runtime (`runtime/src/replay.rs`: mode, logs, compare) so window, input and time natives share them; the window crate gains a `Kind::Replay` beside `Headless`; the CLI gains `--record` and the `replay` command.

**Tech Stack:** Rust (Cargo workspace `kestrel/`), Cranelift 0.137. Tests in `kestrel/runtime/src`, `kestrel/kir/tests`, `kestrel/check/tests`, `kestrel/tests/programs`, `kestrel/tests/errors`, `kestrel/cli/tests`.

**Spec:** `docs/superpowers/specs/2026-10-29-io-round-design.md` (read it whole; decisions 1-10 are numbered there).

**Ledger:** `.superpowers/sdd/2026-10-29-io-round/progress.md` (git-ignored), one line per task, plus each task's brief, report and review.

## Global Constraints

- **Builds and tests:** Idle priority. `CARGO_BUILD_JOBS=8` and `--test-threads=8` when the user is away; 2 and 2 if they are gaming (ask the controller). No benchmark while the user games.
- **Never a visible window:** window programs run with `KESTREL_HEADLESS=<frames>` and `KESTREL_HEADLESS_QUIET=1`, or `KESTREL_HIDDEN=1`.
- **Never call a bare `link.exe`.** On LNK1104 use a short `CARGO_TARGET_DIR` such as `C:/kt/io`.
- **Files under about 400 lines;** split by responsibility. Messages and comments are plain sentences that say what to do.
- **No new syntax** beyond `from_bytes[T](...)` (decision 2), **no new Cargo dependencies.** If `cargo` tries to download anything, stop and report.
- **Natives never `println!`**: output goes through `kestrel_runtime::print`. A native that stops the program uses `fail_at_call`.
- **Every new native and built-in runs in the JIT and in a built exe** (the program tests run both).
- **Never stage** `kestrel/test.kes`, `voxels.exe` or `kestrel/check/src/body/enums.rs` (line endings only).
- **Commit per task on `main`**, message in the repo's style (a sentence saying what changed and why), ending with `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.

## Review Focus

Inputs the spec implies but no task's tests would exercise without these lines; each has its test pinned to the owning task:
1. A `from_bytes` file whose list length claims more items than bytes remain (a 4 GB claim on a 20-byte file) must return `none` before allocating (Task 2).
2. A map encoded with a duplicate key, or a string with a lone surrogate byte sequence, must return `none`, never a map with two equal keys or an invalid string (Task 2).
3. `file.write` to a path whose directory does not exist, `file.read` of a directory, and `file.list` of a file must return `false`/`none` with `file.error()` naming the path (Task 3).
4. A replay file whose native log ends before the program stops calling natives (a longer run) must report the frame and native, not read past the log (Task 5).
5. The voxel engine's edits list must survive a column unloading and reloading: an edited block is back after `unload_far` and regeneration (Task 7).
