# Generics Implementation Plan: `struct Stack[T]`, `enum Result[T, E]`, `best[T](...)`

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Build on `main`, with the ledger under `.superpowers/sdd/2026-10-24-generics/`.

**Goal:** User generics: placeholders on structs, enums and functions (`struct Stack[T]`, `enum Result[T, E]`, `pure best[T: Damageable + Named](...)`), the three built-in rules `equatable`, `ordered`, `key`, square-bracket type arguments in types and expressions, types worked out from values and the expected type, generic code checked once against its rules, and one compiled copy per generic and set of types in the whole program, which runs like the copy you would write by hand.

**Architecture:** The parser reads placeholder lists and parses "brackets after a name" both ways; a syntax pass (`settle.rs`, run at the end of `parse()` and `link()`) turns each into `Index`, `TypeCall` or the new `TypeApply`, so the checker never sees the undecided node. The checker gets `Ty::Param(ParamId)`, interned type lists, and generic types as **instances** (`Stack[int]` is a `StructId` of its own with its fields filled in, so every type question works unchanged); generic bodies are checked once with the strict answers for `T` (R4); calls work out their types (`generic/infer.rs`); after every body, the collection pass (`generic/copies.rs`) appends one `FnInfo` per copy and interns every type a copy's lowering reads, then the tables are frozen. KIR lowering reads every checker type and resolution through one substitution-aware accessor (`lower/subst.rs`) and lowers each copy from the generic's declaration; generic originals become trapping stubs. Range analysis, the inliner, contracts and codegen see ordinary functions.

**Tech Stack:** Rust, Cranelift 0.137. Tests are Rust unit tests plus `.kes` program, error and CLI tests.

**Spec:** `docs/superpowers/specs/2026-10-24-generics-design.md` (committed 236d238), from the approved proposal `docs/superpowers/plans/2026-10-24-generics-proposal.md`. Every message, rule and number comes from the spec, which wins any conflict, except where a **plan ruling** below (P1-P39; P21-P37 from the plan review of 2026-10-25, `.superpowers/sdd/2026-10-24-generics/plan-review-findings.md`) says the spec's text is wrong or silent; each ruling says why and what it costs if wrong. P38-P39 (2026-10-25, from Task 3a's review) are language changes, not spec corrections; Task 3c builds them. Rulings G1-G27 and R1-R8 are the spec's.

## Global Constraints

- **Soundness first.** Generic code is where a copy could become unsafe. Critical bugs, each a stop for review: any answer the checker gives for `T` (or a type containing it) that refuses less code than the R4 table (a `has_heap` of false lets a `string` copy outlive its arena; `is_aggregate` false breaks the exclusivity and changed-later rules); an instance whose owning-ness isn't its declaration's, including **an instance interned after `compute_owning` with no entry in `owning_structs`/`owning_enums`** (`is_owning` reads a missing entry as `false` today: a double free); **an instance with stale per-field flags** (`has_default`, `default_allocates` copied before `mark_default_allocation` ran: `regions.rs` then puts an inferred `Stack()` in region 0 inside `arena { }`, a use after free; P22) or **stale `methods`/`ifaces`** (copied before the declaration's members or `check_conformance`, P23); **a user `TypeCall` mishandled** (a generic call or construction with its types written, `best[int](xs)` or `Stack[int]()`, lowered as a built-in `list`/`map`/`array` call or skipped by an arm that handles the matching `Call`, P28); a type allowed as `T` that R3/R7 refuses (owning, optional, function type, anything holding a function, a missing rule); inference letting the expected type change a placeholder the values decided, or widening a placeholder that must match exactly; lowering reading a checker type or resolution without the copy's substitution, or making a checker type (G13: lowering only looks types up and panics on a miss); a KIR type that names a placeholder layout (a non-concrete struct, enum or element); a copy reusing another copy's closure code, environment layout, list or sort helper, method table or `@prove` site; a recorded conversion or borrow dropped when its substituted source and target differ (G14 drops only equal ones); two different type lists interned as one, or one copy made twice; the driver letting a generic reach KIR before Task 6b; interning that loops on a declaration the expansion check refused. Where a rule is unclear, refuse the program.

## Plan rulings

Each is the plan's, with what it costs if wrong. The ones that correct the spec are flagged **(spec correction)**.

- **P1. The generic tables are one field, `Tables::generic: Generics`** (defined in `check/src/generic/mod.rs`), and `ListMethod` moves from `tables.rs` to `check/src/list_method.rs` (re-exported from `tables`), so `tables.rs` stays under 400 lines with the new `StructInfo`/`EnumInfo`/`FnInfo` fields. - **P2. Copy notes are `Module::copies: HashMap<FuncIdx, CopyNote>`,** not a `Func` field: `Func { ... }` is built in 32 places, and function indexes never change after lowering. Cost: none visible.

  - a body records which of its own `var` parameters it stores such memory into: its summary, including what it passes on to calls that store;
  - each direct call (a function, a method, a generic, a call through an interface or a rule) checks that the caller's current arena and every argument's memory may be stored into the place passed, with `check_store_region`'s own per-context test;
  - summaries are worked out to a fixpoint after every body, so declaration order and recursion don't matter;
  - an interface method's summary is the union of its implementations';
  - a function with a non-empty summary can't be used as a value;
  - closures' own `var` parameters keep today's error.

  More programs are accepted, with no new syntax. Programs accepted today are unchanged: today a storing body is an error, so every summary in a program that checks today is empty. Why: generic containers are unusable without it, and Tasks 4, 6b, 7, 9 and 10 use exactly that `push`. Cost if wrong: an indirect call that reaches a storing function without a check is a use after free. The indirect paths are function values (refused), closures (strict), interface and rule calls (the union) and natives (none has `var` parameters), and the Task 3c review checks each. - **P39. Under R7 an interface type meets only its own interface rule and is never `equatable`, `ordered` or `key`, so `[T: equatable]` and `[T: A + B]` are never interfaces, and their `var` places have exactly their type. So `swap[T: equatable](var a: T, var b: T)` is accepted. `swap[T]` and `f[T: Damageable](var a: T, b: T) { a = b }` stay refused, and the first gets the help "if `T` is never an interface type, give it a built-in rule, like `[T: equatable]`". Cost if wrong: an interface type reaching an `equatable` or two-interface placeholder (through inference or substitution without R7, Task 2b's carried risk) would corrupt the caller's place; Tasks 4 and 5 must run R7 on every worked-out argument.

### Task 3c: Stores into `var` parameters checked at the call — **Opus** (per-task review)

**Goal:** P38 and P39. A function may store memory from the caller's current arena into its own `var` parameters (`push(var self, v: string) { self.items.add(v) }`); each direct call checks that store, the way the checker checks built-in `xs.add(v)` where it is written. Every indirect use keeps a refusal. A whole replacement of a `var` placeholder stays refused unless the placeholder can't be an interface type. This makes `Stack[T].push`, `set_cell[T]`, `fill[T]` and `swap[T: equatable]` check, and also plain `push(var self, v: string)`. There is no new syntax. Programs without such stores check exactly as today.

**The design.**
- **What a body records.** `check_store_region` (`regions.rs`) refuses a store when a context of the value's region doesn't hold the target. If the only failing context is `Ctx::Function`, and the target's root (aliases followed, as `place_root` gives it) is one of the function's own `var` parameters, the store is recorded as a **direct store** `(fn_id, param index)` and isn't reported. The root must be a `var` parameter (`LocalInfo::is_var_param`) of `self.fn_id` (`owner == fn_id`) and not a closure's (`closure` is `None`), and no closure may be being checked (`self.frames` is empty). The param index is the root's position in `FnInfo::locals` (parameters come first, `self` at 0). `main` never records anything: its `Function` context holds every store. A closure's own `var` parameters keep today's error, because a closure is only ever called through a value. The other contexts (`Scoped`, `Scratch`, `Owned`) are still checked after a deferred `Function`, as today.
- **The summary** of a function is the set of its `var` parameter indexes that it may store caller memory into. It holds its direct stores, plus every parameter it passes on to a call that stores into it (see the next bullet). It is conservative about *what* is stored. Inside the callee, all such memory is region bit 0: copies made in the caller's current arena, fresh allocations, and moved arguments. So the call site treats the stored memory as "the caller's current arena, or any argument's memory". Per-source precision buys nothing, because the callee can't tell the sources apart. **Per-type precision is a follow-up**: `Stack[int].push` inside `arena { }` on an outer stack is refused (R4, as for `Stack[string]`), although `si.items.add(1)` written inline is accepted.
- **What a call records** (`check_args`, after `check_exclusive`, only when the arguments bound, `ok`). This covers every direct call: `Res::Fn` calls and method calls (`check_call`, `check_method_call`), written generic calls (Task 3b's `generic_call.rs` goes through `check_args`), inferred calls (Task 4 keeps the line in both modes), and calls through an interface or a rule. For the last two, `check_method_call` passes the interface's **abstract** method as `sig.fid`. For each `var` parameter `i` of `sig`:
  - skip it if `!t.has_heap(sig.params[i].ty)` (the substituted type: `swap[int]`, `Cell[int]`), or if the target has no place root or isn't changeable (`immutable(root)` is `Some`, or `recv.var_root` is `None` for `self`; that error is already reported);
  - otherwise compute `R = current() | region(a, false)` over every argument `a`, the receiver included;
  - judge the target (the argument for `i`, or the receiver for `self`) by the same per-context test `check_store_region` uses (`ctx_holds`, below), for each context in `R`:
    - a failing `Function` context, when the target's root is the caller's own `var` parameter `j` (the same test as a direct store), makes the outcome **propagate** `(caller, j)`;
    - any other failing context makes it **refused**, with the first such context's message;
  - if either outcome is set, push `PendingCall { callee: sig.fid, param: i, caller: Option<(FnId, u32)>, refused: Option<Diagnostic> }`. Nothing about the call depends on the callee's summary except whether this record matters, so the record is complete when it is written.
- **Function values** (`Res::FnValue`: `fn_name_value` in `fnvalue.rs`, and Task 3b's `TypeApply` value in `generic_call.rs`) push `(fid, span)` to `values`. A call through a value (`Res::CallValue`, a field of function type, a constant of function type) can't be checked, so a function whose summary isn't empty is refused as a value. Methods can't be values today, and natives can't be values and have no `var` parameters (none in `driver/std/*.kes`), so their summaries are empty.
- **Interfaces and rules.** An interface's abstract method has no body. Its summary is the union of the summaries of every method that implements it: the method of that name (`FnInfo::name` after its last `.`, as `iface_method` matches it) of every struct and enum whose `ifaces` lists the interface. Instances list their declaration's interfaces and share its method `FnId`s, so a generic struct's methods count once. A call through an interface value (`Res::IfaceCall`) and a call on `T` (`Res::ParamCall`, whose concrete method in any copy implements the recorded rule, R7) are judged by that union. This holds when `T` is an interface type too. Programs today can't have a storing implementation, so their unions are empty and nothing changes for them.
- **Order and recursion.** Bodies are checked in `FnId` order, with constants and field defaults first. They only record; nothing is decided while they are checked. After the last `check_fn` (in `check_keeping_tables`, before `check_map_values`), `var_stores::resolve(t, diags)` works out the summaries:
  1. Start from the direct stores.
  2. Repeat until nothing changes: every pending call whose `(callee, param)` is in the summaries adds its `caller` pair, and every implementation's pair adds the same index to its abstract method. A recursive or mutually recursive function settles in a few rounds, because the sets only grow and are bounded by the number of `var` parameters.
  3. Emit `refused` for every pending call whose `(callee, param)` is in the final summaries, and the value message for every `values` entry whose function has a non-empty summary (naming its lowest summarised parameter).
  4. `std::mem::take` the lists.

  Every index is bounds-checked: an implementation whose signature didn't fit its interface (already an error) or a callee with `Ty::Error` parameters must not panic. This matters for the LSP, which runs `check_keeping_tables` on every edit.
- **Generic code (R1).** A generic function's or method's summary comes from its one checked body. `has_heap(T)` is true (R4), so `T` stores are recorded as for a `string`. Copies (Task 5) share the generic's `FnId` for this purpose; nothing is stored per copy, and KIR reads nothing new.
- **Whole replacement (P39).** `check_iface_replace` (`iface.rs`) still runs before `check_store` in `check_assign` and returns early, so it is never relaxed by the arena change. 6c7258b made it fire for every `Ty::Param` target. Task 3c narrows that to a placeholder that **may be an interface type**: no built-in rule (`equatable` is set by `ordered` and `key` too, G4) and at most one interface rule. Under R7 an interface type meets only its own interface rule and is never `equatable`, `ordered` or `key`, so `[T: equatable]` and `[T: A + B]` can't be interfaces. For those, `var a: T` always gets an exactly-typed place (lending, `lend_var_arg`, is only for a `var I` parameter), and `a = b` is as safe as for a `string`. A refused `T` with no interface rule gets the help "if `T` is never an interface type, give it a built-in rule, like `[T: equatable]`". A `T` with one interface rule keeps the message alone: an `equatable` type can't list an interface, so adding the rule would make the generic useless.
- **What it doesn't touch.** The exclusivity checks (`f(var p.x, p)`, `check_exclusive`), the later-change and kept-part checks, `let ... else` and `match` guards (`check_not_matched` runs on the `var` argument as today), the `par for` write rules, and `@prove(no_alloc)` (KIR-level, unchanged) all run as before. `pure`: a pure function may store into its `var` parameters (it "changes nothing but its `var` arguments"), and its summary works the same. A `par for` body's calls are direct calls in the body's contexts. Its threads' arenas move into the caller's current arena when the loop ends (`runtime/src/par.rs`), as for an inline `add` in the body.

**Messages** (exact; `{f}` is the callee's `FnInfo::name`: `keep_name`, `Stack.push`, `Shelf.put` for a call through an interface or a rule, `fill_any` for a generic; `{place}` is the argument as written, `written(arg)` from `lists.rs`; `{name}` and its type are the variable at the root, as `check_store_region` names it):
- At a call, by the failing context:
  - `Function`: "`{f}` stores memory in `{place}` that is in the caller's current arena, which may not live as long as `{place}`", with help `caller_memory_help(name, ty)` (today's);
  - `Scoped`: "`{f}` stores memory in `{place}` that is freed at the end of the `arena { }` block, but `{place}` lives longer", with help "call it outside the block, or pass a variable declared inside";
  - `Scratch`: "`{f}` stores memory in `{place}` that is freed when the call to `{native}` returns, but `{place}` lives longer", with help "call it before the call to `{native}`, or pass a variable declared inside the argument";
  - `Owned`: "`{f}` stores memory in `{place}` that belongs to `{owner}`, but `{place}` isn't part of `{owner}`", with help "pass a place inside `{owner}`, or call it outside the `in` block".

  The span is the argument passed for the parameter (the receiver for `self`). Two summarised parameters of one call refused give two errors.
- As a value: "`{f}` stores memory from the caller's current arena in its `var` parameter `{p}`, so it can't be used as a value; call it by name instead", with help "a call by name checks that what you pass for `{p}` lives as long as that memory". `{p}` is `self` for a method; the span is the value expression.
- A closure's own `var` parameter: today's "this memory is in the caller's current arena, which may not live as long as `{name}`", unchanged.
- P39's help on today's replace message, for a placeholder with no interface rule: "if `{P}` is never an interface type, give it a built-in rule, like `[{P}: equatable]`".
