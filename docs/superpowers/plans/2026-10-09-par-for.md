# `par for` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run `par for v in xs { ... }` iterations across all cores, with the body rules from the syntax spec checked at compile time, and let `pure` functions take `var` parameters.

**Architecture:**
- The checker enforces the body rules: changes only to the item and the body's own locals, `pure` calls only.
- KIR outlines the body into a function over a range of indexes, called through `Stmt::ParFor`.
- Codegen emits a thunk per outlined body and calls `kestrel_rt_par_for`.
- The runtime runs chunks on a thread pool, gives each thread a temporary arena, and merges those arenas into the caller's current arena when the loop is done.

**Tech Stack:** Rust workspace `kestrel/` (syntax, check, kir, codegen on Cranelift 0.116, runtime staticlib, cli). `std::thread`, `std::sync` only; no new crates.

**Spec:** `docs/superpowers/specs/2026-10-09-par-for-design.md` (read it first; error messages and rules are there).

## Global Constraints

- Source files stay under about 400 lines; new code goes in `runtime/src/par.rs`, `check/src/body/par.rs`, `kir/src/lower/par.rs`, `codegen/src/func/par.rs` (plus the thunk in `codegen/src/par_thunk.rs` if `lib.rs` would grow past 400).
- Error messages are plain sentences that say what to do; use the spec's table verbatim.
- From `kestrel/`, run `cargo test --workspace` and `cargo clippy --workspace --all-targets -- -D warnings`. Also run clippy in `kestrel/godot`.
- Program tests: `tests/programs/*.kes` with `// expect:` lines (JIT and exe). Error tests: `tests/errors/*.kes` with `// error <line>: <message>`; put expectations at the end of the file.
- Write files containing `\n` or `\\` with the Write/Edit tools, not shell heredocs.
- Thread count: `KESTREL_THREADS`, else `std::thread::available_parallelism()`. This machine has 8 cores and 16 threads.

### Task 2: Runtime thread pool and `kestrel_rt_par_for`

**Files:**
- Create: `runtime/src/par.rs`
- Modify:
  - `runtime/src/lib.rs`: `pub mod par;`
  - `runtime/src/arena.rs`: `Arena::absorb`; `program_arena()` honours the job's arena; list growth locks inside a job.
  - `runtime/src/map.rs`: growth locks inside a job.
  - `runtime/src/panic.rs`: `fail` on a pool thread reports to the job and parks.

**Interfaces:**
- Produces: `#[no_mangle] pub extern "C" fn kestrel_rt_par_for(count: i64, body: extern "C" fn(*const u8, i64, i64), env: *const u8, line: i32)`
- Produces: `pub(crate) fn par::shared_growth<R>(arena: *mut Arena, f: impl FnOnce() -> R) -> R`. It runs `f`, holding the job's growth lock when inside a job and `arena` isn't the top of this thread's arena stack.
- Produces: `pub(crate) fn par::job_program_arena() -> Option<*mut Arena>`.
- Produces: `pub(crate) fn par::fail_in_job(msg: &str) -> bool`. It returns false when not in a job. On a pool thread it doesn't return: it records the message, finishes the thread and parks. On the caller it marks the job failed and returns true, and `fail` goes on as usual.

- [ ] **Step 1: Failing unit tests** in `par.rs`:
  - `every_index_runs_once`: counts 0, 1, 7, 1000, 100_003, with the env an `AtomicU8` array, checking each index ran exactly once.
  - `nested_jobs_run_inline`: a body that calls `kestrel_rt_par_for` again.
  - `allocations_survive_the_loop`: the body allocates through `kestrel_rt_alloc` and writes a pointer per index; afterwards every pointer's contents are intact and the caller's arena owns the blocks.
  - `pool_failures_come_back`: call the job runner with a body that calls `fail_in_job` on one index; the caller gets the message back. Test the internal `run_job` function, which returns `Result<(), String>`; the extern wrapper calls `fail` on `Err`.
- [ ] **Step 2: Run** `cargo test -p kestrel-runtime par` and see it fail to compile.
- [ ] **Step 3: Implement** per the spec's Runtime section:
  - a pool of threads fed from an `mpsc` channel of `Arc<Job>`; each participant pushes a fresh arena, takes chunks from `AtomicI64 next`, pops the arena into `job.arenas`;
  - a count of finished participants with `Mutex` + `Condvar`;
  - a thread-local `CURRENT: RefCell<Option<Arc<Job>>>`;
  - the chunk size is `max(1, count / (threads * 8))`.
- [ ] **Step 4: Run** the runtime tests (`--release` too, since races show up there), then commit "Run par for jobs on a thread pool".
