## Start here (2026-10-29; superseded above): fast float math round done

**The fast float math round is finished: built, reviewed, fixed, re-reviewed and measured twice.** `float` transcendental math is now Kestrel's own "wide" functions: at most 0.51 ulp (exhaustive over every `float` input for the one-argument functions), the same bits on every x86-64 CPU and in every build, and inlined as branch-free Cranelift code with one branch to a cold call for special inputs, except `pow`, which is a call. Pure math whose operands a loop never changes is computed once before the loop. Everything is on `main` and pushed through ccc2eee; the doc commit after it is this handoff's.

- **Why:** the user asked for faster deterministic math after the determinism round ("for games math is a huge part"); determinism had made `pow` 2.7 times slower than the C runtime's and the `step_pow` particle kernel 2.02 times slower.
- **What was built:**
  - **Wide functions** (`kestrel/runtime/src/math/wide.rs`, `wide/*.rs`): `sin cos tan asin acos atan atan2 exp log pow` and float `%`, computed in `f64` from `+ - * /`, exact steps and `sqrt`, rounded once to `float`. No C runtime math, no float-to-int conversion. Special inputs (NaN, infinities, zeros, out-of-domain and huge arguments) are classified by integer bit tests and take today's `libm` path, so they keep today's bits. Every coefficient is a `pub const` there, and codegen reads it from there.
  - **`pow` exact exponents:** `y` of exactly 1, -1, 2 or 0.5 (tested on `y`'s bits, so on its value, never on a literal's shape) gives `x`, `1/x`, `x*x` and `sqrt(x)` for `x > 0`, which are `libm`'s own early returns, so today's bits. Other exponents (including -2) are wide, within 0.5 ulp; exact midpoints such as `pow(2, -150)` can round away from even (entry 53).
  - **Inline code** (`kestrel/codegen/src/func/wide*.rs`, `wide_pick.rs`): each helper mirrors its Rust twin op for op. The fast path has no branch but the special-input `brif`: picks on float compares are a vector compare and a blend (or `minpd`/`maxpd`) in the float registers; picks on integer conditions are integer `select`s (`cmov`); constants are the second operand of adds and multiplies so x64 reads them from memory. `sin(a)` and `cos(a)` share one reduction. Tests (`codegen/tests/wide_math.rs`, `wide_branches.rs`) check the inline code against the Rust functions on every sweep input in checked and release builds, and the machine code for one branch, one call, no hidden-jump sequences, no float-to-general-register round trips and no rebuilt constants.
  - **Hoisting** (`kestrel/kir/src/hoist.rs`, last in `optimize`): pure `float` math whose operands a loop never changes moves before the loop, innermost loops first, seeing through the inliner's parameter temporaries. A `par for` passes its `float` captures as copies, so `pow(KEEP, dt)` in a particle step leaves both the frame loop and the `par for`. `--report` and contract text print a hoisted value as the expression it replaced, so they are byte-identical (700 outputs compared).

## Start here (2026-10-28; superseded above): determinism round 1 done

**The determinism round is finished: built, reviewed, fixed, re-reviewed and measured.** A Kestrel program can now promise, and the compiler checks, that the same inputs give the same bits on every CPU and at any thread count, and a game can save, restore, compare and replay its state cheaply. Everything is on `main` and pushed through 6c9a023; the doc commit after it is this handoff's (not pushed; the controller pushes).

- **Why:** the user asked what would make Kestrel unique among game languages. The controller wrote two proposals (`docs/superpowers/plans/2026-10-27-determinism-proposal.md` and `2026-10-27-gpu-proposal.md`); the user picked "Determinism first" on 2026-10-27, with `par gpu for` and Kestrel shaders next. Names are as the proposal recommended.
- **What was built:**
  - **Own math:** `sin`, `cos`, `pow`, `exp`, `atan2`, `fmod` and the rest of the transcendental functions (scalar, f32 and SIMD) are computed by Rust's `libm` crate, linked into the runtime and the JIT, not by the C runtime, so the bits don't depend on the CPU or the C library. No math path is left on the C runtime (reviewed). The JIT's copy gets libm's `arch` feature; the only differences under it are `sqrt` (correctly rounded either way) and `fma` (never called), so results are equal.
  - **Float mode:** MXCSR is pinned at start, in every `par for` thread, after every window-library native returns, and for the compiler's own thread in `run()`. **The baseline ISA is SSE4.1** for exes and the JIT (no FMA, no AVX), so contraction can't change a result.
  - **`par for` failures:** a failing `par for` reports the lowest failing iteration index whatever the thread count or timing.
  - **`@prove(deterministic)`:** a contract that refuses a function (and what it calls) that reaches a source of nondeterminism, such as the shared global random generator (`randf`, `randf_range`), a clock or a window or input read; it also checks that the state the function changes (`var` parameters, fields) can be copied and checksummed, with the written chain of calls in the error. The snapshot check refuses exactly what `checksum` refuses: owning types (an `Arena` or GPU object), interface values and all function values.
  - **`random` module:** built-in `Rng(seed:)`, a seeded SplitMix64 generator whose state is a plain value, so it copies, saves and compares like any other.
  - **`checksum(x) -> i64`:** a content hash of any value that owns nothing. It hashes only a list's `len` items, never `cap` or an arena, so two lists with different histories hash equal.
  - **Storage-reusing assignment** for lists, strings, structs, enums and maps: assigning over an existing value with room reuses its storage instead of allocating (a map's entries and index too, when it isn't being looped over), so saving and restoring plain game state proves `no_alloc`. Field-disjoint paths count as non-overlapping (`p.ring[k] = p.game` reuses); a target index with a call or any write keeps today's copy; a par for item field assigned from a captured value reuses (each thread writes only its own item's buffers).
  - **Cross-build test:** `kestrel/cli/tests/determinism.rs` checks that the JIT, `run --release`, a checked exe and a release exe print the same checksums and math bits for `det_rng_checksum`, `det_sim`, `det_snapshot`, `det_par` and `det_math` (programs in `kestrel/tests/programs/det_*.kes`), at 1, 2 and 16 threads.
  - **Rollback Pong:** `kestrel/demos/pong/` (`pong.kes`, `game.kes`, `net.kes`, `peer.kes`, `replay.kes`): two peers in one process over a simulated network with delay, jitter and loss, prediction and rollback, a checksum compare every 30 frames and an in-memory replay. Tested headless (`kestrel/cli/tests/pong_demo.rs`, 5 tests) in three builds.

- **What changed in the compiler:**
  - Functions are processed callee-first over the strongly connected components of the call graph (Tarjan); each is inlined into once, and its callers see the body and its size after its own inlining.
  - A call is inlined when the callee is inlinable as before, **`MAX_NODES` 256 as written** (a function written big stays a call; `Builder.face` is 258, entry 20, still open), **`POST_LIMIT` 4,096 nodes after its own inlining**, and the caller's **`BUDGET` 8,192 nodes per function** (charged only for direct copies) has room. A copied body is not walked again.
  - When the budget can't fit every call, **calls in deeper loops go first**, then program order. Calls inside a one-level copy of a cycle-mate are not ranked by loop depth (a rare shape, bounded by the budget).
  - Mutual recursion: a callee in the caller's own cycle is inlined one level only, from its original body, not held to the 4,096 limit (bounded by the budget); the reason for the call left in the copy is "it calls back into ...". Directly recursive functions are never inlined (as before).

**Plan 2 rulings made on the user's behalf** (what each costs if wrong):
- **A. Natives use Kestrel's own calling convention:** aggregates by pointer, a string is a pointer to its 16-byte header, an enum a pointer with the tag first, an aggregate result through a pointer passed first, `bool` and `u8` zero-extended. The first design said "pointer and length" and "enum as its tag". Cost: a native reads one more indirection.
- **B. `FnDecl.is_native: bool` with an empty body block,** instead of `Option<Block>`. Cost: a bodyless function looks like an empty one to code that forgets the flag (the inliner was fixed explicitly).
- **C. Constants** (changed in the final review): constants are checked in dependency order, a depth-first walk over the constants each one uses. So `let BG = draw.BLACK` works, a module's `pub let SKY = draw.BLUE` works whatever the `use` order, and a constant may use one declared below it. A loop (`let A = B`, `let B = A`) is an error that names it. Without a dependency, a module's constants still come before the entry file's. Cost: none known; the old "earlier constants" message now says "other constants".
- **D. Headless lines quote strings.** Cost: none (a test-only format).
- **E. Memory is measured with a runtime arena report** (`KESTREL_ARENA_REPORT=1`), not a process's working set. Cost: one more test-only environment variable.
- **F. All subagents on Sonnet** (the user is asked before Opus).
- **G. A native struct parameter may have `string` fields.** Cost: none; a one-line change in `check/src/natives.rs::param_ok`.
- **H. The `builtin_modules.kes` program test moved to Task 5,** because the JIT needs every native registered; a driver test with no-op natives covers Task 3. Cost: none.
- **I. Native parameters skip the linker's "already imported" name check,** so `draw.text(text: string, ...)` stays as written. Cost: none observable.
- **J. Struct constructions are allowed in constants only.** A field default may construct only `vec2` and `vec3`, and can't use a constant whose type holds a user struct; `default_allocates` is conservative. This closed a dangling default and a default cycle. Cost: `tint: Color = draw.WHITE` isn't available yet. (Since the first language pass, 2026-10-12, a default may be a struct or enum value that doesn't own an `Arena` or a GPU object, so `tint: Color = draw.WHITE` works; the vec2/vec3-only rule is gone.)
- **K. The memory test's control text is longer than `"n {n}"`,** because the brief's text grows only 655,360 bytes in 100,000 frames, under the control's 1 MiB bound. The real program still uses `"n {n}"`. Cost: none.
- **L. The checker treats a native call's arguments as a scoped region** when one is directly an interpolated string, like `arena { }`: "this memory is freed when the call to `draw.text` returns, but `x` lives longer". Cost: exotic code (a store inside such an argument's block) gets an error instead of compiling.
- **M. `window.frame()` flushes `print` output each frame** (Task 8). `print` is buffered until the program ends, so without this the demo's once-a-second lines would show only at exit. Cost: one flush per frame, which is a stdout lock when nothing was printed and a write when something was.

### The final review (fixed after plan 2)

The final whole-branch review found, and these commits fixed:
- **Constants were checked in load order**, so `palette.kes` with `pub let SKY = draw.BLUE` failed unless `use draw` came first (ruling C).
- **`struct Node { next: Node? }` crashed the compiler** (stack overflow in KIR layout). An optional holds its payload in place, so it is now a "contains itself" error (with a help line pointing at `list[Node]` and `[Node]`, which keep their items elsewhere), also for mutual cycles (`A { b: B? }`, `B { a: A? }`). KIR's `has_heap` also guards against a type it is already inside.
