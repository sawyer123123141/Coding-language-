## Done (all on `main`, pushed)

- **The compiler** (`kestrel/`): syntax → check → KIR → Cranelift (JIT and exe), plus runtime and driver.
- **Language features:**
  - functions, `pure`
  - structs and methods; enums and `match`
  - `vec2`/`vec3`; strings with print-only interpolation
  - arrays `[T]`, `list[T]`, `for in`
  - optionals `T?` with `let x = opt else { ... }`
  - modules (`use m`, `use { a from m }`, `pub`)
  - bit operators `& | ^ ~ << >>`
  - arenas (`arena { }`, `in x.mem { }`), owning values that move, drops, and an escape check
  - checked arithmetic, with `--release` turning checks off
- **A KIR inliner** for small functions.
- **The Godot add-on** (`kestrel/godot`, its own Cargo workspace on godot-rust 0.5.5):
  - `Kestrel.new()`, `load`, `run`, `refresh` (hot reload), `functions`, and a `checks` property.
  - A demo of voxel terrain in `kestrel/godot/demo`, with a headless test at `demo/tests/test_bridge.gd` (26 checks).
  - The C# vs Kestrel vs GDScript benchmark lives in `kestrel/godot/bench`.
- **Benchmarks:** `kestrel/bench/2a` (small kernels vs Rust and C), `kestrel/bench/heightmap` (milestone, about 3.2x Rust), `kestrel/bench/voxels` (about equal to C# after arena block recycling).
- **Status:** 177 tests pass, and clippy is clean in both workspaces.

## Next: a heavier voxel benchmark (the user asked for this)

The current voxel benchmark takes about 11 ms per build: too small to show much. Build a heavier one that still uses voxels:

- **The world:** a full 3D voxel world, not a heightmap. For example 8×8×8 chunks of 32³ blocks (about 16.7M voxels).
  - Density comes from 3D value noise, several octaves (8 lattice lookups per octave), so there are caves and overhangs.
  - Then face-culled meshing: a face for each solid voxel next to air.
  - Aim for about 0.5–2 s per run in Kestrel and C#, so differences are clear.
- **Same three-way setup as `kestrel/bench/voxels`:**
  - Kestrel exe (checks on and off) vs a C# .NET 9 console app, timed over a few runs with startup subtracted.
  - Inside Godot as well, via `kestrel/godot/bench/bench.gd`.
  - GDScript only on a small slice, then scaled up (the full run would take minutes).
- **Use `arena { }` per chunk or per round** (idiomatic, and it recycles memory).
- **Record results** in a new `kestrel/bench/voxels3d/results.md`, honestly.
- **It sets up `par for` later:** chunks are independent and `pure`, so a multi-core version should beat single-threaded C# clearly.

## Environment and gotchas

- **Godot:** 4.7.2 Mono at `C:\Users\sawye\Desktop\Godot_v4.7.2-stable_mono_win64\Godot_v4.7.2-stable_mono_win64\`.
  - Use `..._console.exe` with `--headless`.
  - Run `--import` once per project, then `--script res://...`.
  - Frames can be rendered to PNG with `--write-movie out.png --quit-after 5`.
- **.NET:** SDK 9 is installed.
  - Godot C# builds need `-p:RestoreAdditionalProjectSources=<Godot>\GodotSharp\Tools\nupkgs`.
  - Build with `-p:Optimize=true`: Godot's Debug configuration otherwise disables JIT optimizations.
- **Add-on:** build with `kestrel/godot/build.ps1` (release), and close Godot first, because Windows locks the DLL.
- **Shell escaping:** shell heredocs sometimes mangle `\n` and `\\` (a command hook rewrites commands). Write files that contain escapes with the Write/Edit tools, or with Python scripts written via Write.
- **Flaky test:** the `relocated` CLI test occasionally fails with "file in use" (OneDrive or antivirus locking a copied exe). Re-run it.
- **Benchmarks:** this machine is noisy. Use medians, repeat runs, and report ranges.

## Known gaps

`docs/superpowers/plans/2026-10-09-core-2a-followups.md` lists them. The notable ones:
- A `pure` function can't call a helper that fills a `var` local.
- `let ... else` always moves or copies.
- Runtime errors don't name the file.
- The add-on is Windows-only.
- The Godot bridge costs a few ms per 32 calls (the hop to its worker thread).
