  - **A. Moves follow the program's paths.** `if c { a.add(t) } else { b.add(t) }` compiles. A move on a path that returns, breaks or continues doesn't count after it. Assigning a moved `var` gives it back. A move inside a loop is fine when the loop leaves right after it or the variable gets a new value first. A use after a move on some paths says "`t` may have been moved earlier" (it can't point at the move: the checker has no line numbers). KIR and codegen didn't change, because a move already zeroes its source and every drop skips a zeroed value.
  - **B. Views.** Moving a variable while a `match` arm's binding reads it is an error now (it used to compile and read freed memory). `let x = opt else { ... }` reads the payload in place, with no copy and no move, when `opt` is a place whose root can't change (a `let` local, a non-`var` parameter, or `self` in a method that takes `self`) and the payload holds heap memory or owns something; so `let t = self.tex else { return }` works on a GPU texture field. `var x = opt else`, a `var` root and a whole owning local still move or copy. A call whose receiver is also passed as `var` (`c.poke(var c)`) is refused: an older gap that views made unsafe.
  - **C. Defaults and constants take struct and enum values** (`tint: Color = draw.WHITE`, `state: State = State.Idle`, `inventory: Inventory = Inventory()`), but not values that own an `Arena` or a GPU object (`Arena()` itself is allowed). A new check reports defaults and constants that build each other forever, once, with the loop spelled out.

A construction missing several fields lists them all. `let velocity: vec3()` says a type goes after `:` and the value after `=`. - **PowerShell 5.1:** `Set-Content -Encoding utf8` writes a byte order mark. Kestrel now accepts one in any file, including modules.
- **Add-on:** build with `kestrel/godot/build.ps1` (release), and close Godot first, because Windows locks the DLL.
- **Shell escaping:** shell heredocs sometimes mangle `\n` and `\\` (a command hook rewrites commands). Write files that contain escapes with the Write/Edit tools, or with Python scripts written via Write.
- **Window programs:** raylib is vendored in `kestrel/window/raylib`, and `cargo test --workspace` builds it (a cold build compiles it twice). Window tests run headless through `// env: KESTREL_HEADLESS=...`. The test harness is hermetic (it removes every `KESTREL_*` variable from each child before applying the program's `// env:` lines), and it panics for a program that calls `window.open` without a `// env: KESTREL_HEADLESS=...` line. `kestrel run` of a window program opens a real window; `KESTREL_HIDDEN=1` hides it (the GPU smoke test uses that).
- **Measuring window programs:** Kestrel can't read environment variables, so the demo prints its own lines (one a second). `print` output is flushed once per `window.frame()`. A visible window waits for vsync, so the display's refresh rate (60 Hz here) caps its fps. A hidden window (`KESTREL_HIDDEN=1`) does not wait for vsync on this machine, so judge 60 fps from frame time there.
- **Flaky test:** the `relocated` CLI test occasionally fails with "file in use" (OneDrive or antivirus locking a copied exe). Re-run it.
- **Benchmarks:** this machine is noisy. Use medians, repeat runs, and report ranges. To compare two compilers, build the old one in a git worktree at a short path (`C:\kt\...`: the nested runtime build under a long scratchpad path hits Windows' 260-character limit) and run old and new one after the other, taking turns. A small loop's time can move 6-30% with where the code lands; add an unused function to the program to see whether a difference is real. `bench/maps` is the most sensitive to other programs (229 ms in a quiet hour, 305-2,557 ms in a busy one).

## Known gaps

- **The runtime keeps freed arena memory.** A freed arena's blocks go to a per-thread spare cache (up to 256 MiB, `kestrel/runtime/src/blocks.rs`) instead of back to Windows, so after the voxel viewer's one-off build arena the process keeps about 172 MiB (headless, `WIDTH = 8`). The follow-ups list fix ideas (don't cache big blocks, or trim the cache after an unusually large arena); the user decides.

`docs/superpowers/plans/2026-10-09-core-2a-followups.md` lists them. The notable ones:
- Views over a `var` root still copy (`let ... else` on a `var` local, a `var` parameter, or `var self`).
- `var x: T` with no value is a syntax question for the user.
- (The first language pass closed three that were listed here: a `pure` function calling a `pure` helper that fills a `var` local already worked; `let ... else` reads in place when it can; runtime errors name the file.)
- The add-on is Windows-only, and so is the standalone window (the window must move to the main thread for macOS).
- The parser refuses code nested more than 1,000 levels deep (since 2026-10-17). Deeply nested range loops still compile slowly (follow-ups).
- The Godot bridge costs a few ms per 32 calls (the hop to its worker thread).
