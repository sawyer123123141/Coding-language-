## Done (all on `main`, pushed)

- **The compiler** (`kestrel/`): syntax → check → KIR → Cranelift (JIT and exe), plus runtime and driver.
- **Language features:**
  - functions, `pure` (may take `var` parameters, including `var self`)
  - structs and methods; enums and `match`
  - `vec2`/`vec3`; strings as heap values, with interpolation anywhere (`let s = "hp {hp}"`)
  - global math (`sqrt sin cos tan asin acos atan atan2 exp log pow floor ceil round abs sign min max clamp lerp PI TAU`), vector methods (`length normalized dot distance_to`) and random numbers (`randf randf_range randi_range rand_seed`): plan 1 of the window work
  - arrays `[T]`, `list[T]`, `for in`
  - optionals `T?` with `let x = opt else { ... }`
  - modules (`use m`, `use { a from m }`, `pub`)
  - bit operators `& | ^ ~ << >>`
  - `map[K, V]` (`docs/superpowers/specs/2026-10-09-map-design.md`):
    - GDScript-style `{"a": 1}` literals; `m[k]` is a `V?`; `m.get(k, d)`, `has`, `remove`, `.len`; `for k, v in m` and `for k in m`, in insertion order.
    - Keys are integers, bools or strings. String `==` came with it.
    - Adding a key inside a loop over the same map panics; removing is fine.
  - `par for v in xs` (`docs/superpowers/specs/2026-10-09-par-for-design.md`):
    - Iterations run on all cores.
    - The body may change only its item and its own variables, and call only `pure` functions; the checker enforces it.
    - The runtime pool merges each thread's arena into the caller's.
    - `KESTREL_THREADS` sets the thread count.
  - arenas (`arena { }`, `in x.mem { }`), owning values that move, drops, and an escape check
  - checked arithmetic, with `--release` turning checks off
- **A KIR inliner** for functions up to 256 KIR nodes, 8 calls deep (including calls in the arguments of inlined calls), with a budget of 4,096 added nodes per caller.
- **The Godot add-on** (`kestrel/godot`, its own Cargo workspace on godot-rust 0.5.5):
  - `Kestrel.new()`, `load`, `run`, `refresh` (hot reload), `functions`, and a `checks` property.
  - A demo of voxel terrain in `kestrel/godot/demo`, with a headless test at `demo/tests/test_bridge.gd` (25 checks; earlier notes said 26, which was a miscount: there were 24, and the final review added one that returns a built string).
  - The C# vs Kestrel vs GDScript benchmarks live in `kestrel/godot/bench` (`bench.gd` for the 2D voxels, `bench3d.gd` for the 3D world).
- **Benchmarks:**
  - `kestrel/bench/2a`: small kernels vs Rust and C.
  - `kestrel/bench/heightmap`: the milestone, about 2x Rust with `--release`.
  - `kestrel/bench/voxels`: the Godot demo's mesher, now faster than C#.
  - `kestrel/bench/voxels3d`: a full 3D world (8×4×8 chunks of 32³, 3D noise, face-culled meshes).
    - One thread: Kestrel `--release` 0.46 s, checks on 1.07 s; C# 1.45 s as written, 0.54–0.64 s with `[AggressiveInlining]`; GDScript about 170 s.

  - `kestrel/bench/maps`: `map` vs C# `Dictionary`. Kestrel is behind on all three workloads: string keys about 10%, scattered integer keys 1.3x, in-order integer keys 2.5x (C#'s identity hash walks memory in order). See its `results.md`.

## Now: a standalone window (sub-project 4b), plan 2

**Designed:** `docs/superpowers/specs/2026-10-10-window-design.md`.
- The user picked the syntax: a program-owned loop (`while window.frame() { }`), three modules (`window`, `draw`, `input`), Godot float colours, `input.held/pressed/released`, global math like GDScript, and the `native` keyword.
- This spec is 2D only. 3D, textures and the voxel viewer get the next spec.
- raylib's C source is vendored and compiled with the `cc` crate, because `raylib-sys` needs LLVM (libclang) and this machine has none.

**Plan 1 is done** (`docs/superpowers/plans/2026-10-10-window-1-language.md`): math, vector methods, random numbers, and strings anywhere. It ran subagent-driven on Sonnet, and all six tasks were reviewed.
- The ledger is `.superpowers/sdd/2026-10-10-window-1-language/progress.md`. It is git-ignored and local to this machine; it has every ruling and the deferred minor findings.
- **Task 2** (strings anywhere) took three fix rounds: map keys built in an arena weren't copied on insert; then the key copy needed the same freshness rule as every other copy; then `block_value` copied literals that the checker treated as static.
- **Task 3** (math) took one: `PI` and `TAU` are exact when they meet an `f64`.
- **Task 4** (min/max and vector methods) took one: an indexed vector place is copied so its index is evaluated once.
- Tasks 1, 5 and 6 were clean.

**Next is plan 2, the window itself:** the `native` keyword, the built-in modules (`window`, `draw`, `input`), vendored raylib, the window crate, linking, headless mode, the smoke test and the particles demo. Plan 2 isn't written yet. Write it from the spec, then run it the same way.

**Carry into plan 2** (hazards the plan 1 final review found for code that doesn't exist yet):
- **Natives that read strings** must handle `ptr = null, len = 0`: an empty interpolation and a zero-filled `array[string]` element both look like that. Never call `slice::from_raw_parts` on a null pointer.
- **The scratch arena around a native call's interpolated arguments** must be a real cleanup scope, like `arena { }`, so a `return`, `break` or `continue` inside an argument expression pops it.
- **Built-in modules and the demo should pass strings, not store them.** Storing a non-literal string takes an `Arena` owner (`in x.mem { }`).

**Rulings made on the user's behalf** (each with what it costs if wrong; full list in the ledger):
- **Strings are heap values now,** like arrays: copying one copies its bytes, and the escape check covers them.
  - Storing a non-literal string into a longer-lived place needs `in x.mem { }`, for example `self.name = n` through `var self`.
  - Cost if wrong: string-heavy code is clumsier; a friendlier rule would be a language change.
- **String-key maps are 35% slower** in `bench/maps`, because `let w = words[i]` now copies. Accepted for now; there's a follow-up to let read-only copies share bytes.
- **Map keys are copied when they add an entry,** decided in KIR with the same freshness rule `owned` uses for every copy. Cost if wrong: an extra key copy.
- **`block_value` hands back a `Move` of its spill:** when a block declares an owning local, its tail goes through `owned(..)` into a temp and the temp is moved out. Cost if wrong: a missed or doubled copy for some tail shape. One shape still dangles (see the follow-ups).
- **Math names are reserved** like `print`, with the existing message "`min` is a built-in name; pick another". The vector method names aren't reserved.
- **`randf` stays below 1 at `float`:** a demoted 1.0 becomes 0.99999994, so `int(randf() * n)` never indexes past the end. Godot's `randf` is inclusive. Cost if wrong: a one-in-33-million draw differs.
- **`operand` copies indexed vector places,** so the index is evaluated once (`vs[next()].length()`). It also fixed vector `+` and swizzles. Cost if wrong: an extra copy of an indexed vector per operation.
- **All subagents run on Sonnet,** the final review included.
- **Fixed in the final review:** a `T` used as a `T?` wasn't copied (`in h.mem { h.s = k }` with `s: string?` or `[int]?` dangled, as did `Player(name: n, nick: n)`). `owned` now copies the payload of a `Some`; `tests/programs/optional_copies.kes` covers it.

- **Open from `par for`:** SIMD, the other half of sub-project 3 in the syntax spec, isn't started.
- **Checks cost 2.4x on the 3D world**, because each overflow check is a branch that keeps work in the loop. Range analysis could drop many of them; the follow-ups list has the details.

## Environment and gotchas

- **Godot:** 4.7.2 Mono at `C:\Users\sawye\Desktop\Godot_v4.7.2-stable_mono_win64\Godot_v4.7.2-stable_mono_win64\`.
  - Use `..._console.exe` with `--headless`.
  - Run `--import` once per project, then `--script res://...`.
  - Frames can be rendered to PNG with `--write-movie out.png --quit-after 5`.
- **.NET:** SDK 9 is installed.
  - Godot C# builds need `-p:RestoreAdditionalProjectSources=<Godot>\GodotSharp\Tools\nupkgs`.
  - Build with `-p:Optimize=true`: Godot loads the Debug build, which otherwise disables JIT optimizations. `kestrel/godot/bench/run.ps1` does this.
- **PowerShell 5.1:** `Set-Content -Encoding utf8` writes a byte order mark. Kestrel now accepts one in any file, including modules.
- **Add-on:** build with `kestrel/godot/build.ps1` (release), and close Godot first, because Windows locks the DLL.
- **Shell escaping:** shell heredocs sometimes mangle `\n` and `\\` (a command hook rewrites commands). Write files that contain escapes with the Write/Edit tools, or with Python scripts written via Write.
- **Flaky test:** the `relocated` CLI test occasionally fails with "file in use" (OneDrive or antivirus locking a copied exe). Re-run it.
- **Benchmarks:** this machine is noisy. Use medians, repeat runs, and report ranges.

## Known gaps

`docs/superpowers/plans/2026-10-09-core-2a-followups.md` lists them. The notable ones:
- A `pure` function can't call a helper that fills a `var` local.
- `let ... else` always moves or copies.

- The add-on is Windows-only.
