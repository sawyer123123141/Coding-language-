# Closures and List Methods Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add function types, named functions as values, closure literals with by-value path captures, and the list methods `filter`, `map`, `any`, `all`, `sort`, `sort_by`.

**Architecture:** Each feature runs through `syntax → check → kir → codegen`. A function value is an aggregate `{code, env}`. Closure code is a KIR function taking the environment pointer first. The environment holds captured values (shallow on the stack for a literal that is directly a call argument, deep in the current arena otherwise). The list methods are generated helpers per call site that call a literal closure's code directly, so `inline_small` removes the call; `sort`/`sort_by` call a runtime stable sort with a generated less-than function. The templates are:
- **Outlining:** `par for` (`check/src/body/par.rs` frame, `kir/src/lower/par.rs` outlining, `codegen/src/func/par.rs` + `par_thunk.rs` env and `func_addr`).
- **Generated per-type helpers:** `has`/`find` (`kir/src/lower/list_helpers.rs`).
- **Scratch arenas:** natives (`kir/src/lower/call.rs` `scratch_parts`).

**Tech Stack:** Rust, Cranelift. Tests are Rust unit tests plus `.kes` program and error tests.

**Spec:** `docs/superpowers/specs/2026-10-18-closures-design.md`. Every message and behaviour below comes from it, and the spec wins any conflict. The `@` spec (`2026-10-18-at-annotations-design.md`) is not built in this plan.

## Review Focus

1. **A stack environment outliving its call.** Any path that stores, returns or copies a function value with a stack environment without deep-copying it is a dangling pointer into a dead frame. Task 4 adds a KIR debug check (a stack-environment `MakeFn` only as a direct `Arg` of a call) that runs in every test build, plus the spec's `run(if c { ... } else { h })` and `fs.add(...)` programs.
2. **Captured values sharing memory after a copy.** `let g = () { xs }`, two results changed separately; a stored closure copied, then the copy's capture changed through a returned value; a closure capturing a closure. (Tasks 3 and 4.)
3. **A capture read stale or changed during a call:** `promote` keeping a captured field in a register, the exclusivity rule's every source (var args, `var self` receiver, sort receiver, callee place, sibling arguments), views followed to their source. (Tasks 4 and 5.)
4. **Memory growth in frame loops:** a closure literal passed to a function-typed parameter (0 bytes), `sort_by` with an allocating key (flat), a stored closure reassigned (constant per assignment). (Tasks 4 and 6.)
5. **Parsing:** `if (ready) { }`, `in (w.mem) { }`, `while (x > 0) { }`, `match (e) { }` and `for v in (xs) { }` unchanged; a multi-line closure body inside call parentheses; a closure followed by `.`, `[` or `(` on the next line. (Task 3.)
