# Fast Deterministic Float Math Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `float` transcendental math that is fast, at most 0.51 ulp from the true value (measured exactly and reported per function), and bit-identical everywhere:
- "wide" Rust functions are the reference;
- the compiler inlines them as branch-free Cranelift IR with one special-input branch to a runtime slow path;
- a KIR pass hoists pure math with loop-invariant operands out of loops.

**Architecture:**
- **Runtime:** `kestrel_runtime::math::wide` holds the constants and the Rust functions, exported as `kestrel_rt_<op>f`. `kestrel_rt_fmod_f32` keeps its name. A doc-hidden `math::sweep` module holds the test inputs and the ulp measure.
- **Codegen:** `codegen/src/func/wide*.rs` mirror the Rust helpers one for one and read the same constants. `pow` stays a call.
- **KIR:** `kir/src/hoist.rs` runs last in `optimize`.
- `f64` math is unchanged (`libm`).

**Tech Stack:** Rust (Cargo workspace `kestrel/`), Cranelift 0.137, `libm` 0.2.16. Tests in `kestrel/runtime/src/math/`, `kestrel/codegen/tests`, `kestrel/kir/tests`, `kestrel/tests/programs`, `kestrel/cli/tests`.

**Evidence:** `.superpowers/sdd/fastmath-spike-report.md` and `fastmath-spike.patch`. Read `kestrel/runtime/src/math/fast.rs` and `fast_test.rs` in the patch. Port from them with the changes Task 1 lists; **never `git apply` the patch**.

## Review Focus

The five inputs most likely to bite (every review of Tasks 1, 3 and 4 tries each):

1. **Huge arguments and range edges.**
   - `sin`/`cos`/`tan` at the fast-range bound: `399999968`, `400000000`, `400000032`, `1e30` and `f32::MAX`.
   - The quadrant for large `k`, which comes from `bits(t) - bits(ROUND)` and must agree with `k` near 2^28.
   - `exp` at the clamps: `88.72`, `88.73`, `89`, `-103.97`, `-104` and `-110`.
   - `%` whose quotient is right at 2^29, and whose quotient rounds up in the division (the fix-up step).
2. **Subnormals and signed zeros.**
   - `sin`, `tan`, `atan` and `asin` of `-0.0` and of a subnormal must return the input itself. The tiny pick (a bit test, `A < bits(TINY)`) does that; the polynomial turns `-0` into `+0`.
   - `atan2(±0, -x)`, and `acos(-0) == acos(0) == π/2`.
   - `log` of `1e-45` and of the largest float.
   - `exp` results that are subnormal floats (x near -100), rounded once from `f64`.
   - `%` with a subnormal divisor, and a zero result, which takes the sign of `a`.
3. **NaN and infinities take the slow path**, from the integer bit test of spec decision 2, written the same on the IR side and the Rust side, so both classify every input alike, also under DAZ or FTZ. A float compare on either side, or a signed compare where the spec says unsigned, is a finding. Payloads aren't promised, but the result must be a NaN. `exp(±inf)` stays on the fast path through the clamps (`+inf` gives `inf`, `-inf` gives `+0`).
4. **Selection boundaries**, where a pick changes sides:
   - odd multiples of π/4 (the quadrant), `|y| == |x|` in `atan2` (the swap), and `num == TAN_PI_8 · den` (the `big` reduction);
   - `asin`/`acos` at `±1` and `±0.99999994`;
   - `log` at the √½ split and at `1 ± 1 ulp`;
   - `exp` where `k` steps.
5. **Mirroring.** The JIT, the checked exe, the release exe and the Rust function must agree on the same inputs, including inline code next to other inline code. `sin(a)` and `cos(a)` share their reduction through GVN, and values live across the slow-path call. A constant typed twice, or an operation reordered (`(s*w)*p` against `s*(w*p)`), is a finding even when today's tests pass.

**For the hoisting pass (Task 5):**
- an inliner temporary (`let dt2 = dt` in the loop body) seen through; one `let` after a use, inside an `if`, assigned again, or reading another temporary, not seen through;
- an operand written only in an `if` branch, through a `var` argument or in an inner loop;
- the loop variable;
- a loop that runs zero times;
- a `par for` capture;
- an operand built with checked integer arithmetic;
- float `%` by an invariant zero.

**The algorithms** (each Rust helper is the definition the IR mirrors):
- **The spike's `wide_*`,** with these changes:
  - Rounding is `round_k`, not `rint64` plus `as i64`.
  - Selects are plain `if`s; drop `pick64`/`pick32` and their `asm!`.
  - `trunc` is `libm::trunc`.
  - Every special path is `today`'s expression: `libm::sin(x as f64) as f32`, ..., `libm::fmodf(a, b)`. `expf(NaN)` too.
  - **Every special test is the bit test of spec decision 2** (`wide::special`), never a float compare. That includes the tiny pick. The IR emits the same integer operations on the same bit patterns.
  - `ulps` takes the exponent from `r`'s bits, not from `log2`.
- **`sin`, `cos`, `tan`:**
  - `(r, k) = reduce(x)`, then `(s, c) = sin_cos_poly(r)`.
  - `sin`: `flip(if k & 1 == 0 { s } else { c }, k)`.
  - `cos`: the same with `k + 1`.
  - `tan`: `let (n, d) = if k & 1 == 0 { (s, c) } else { (-c, s) }; n / d`.
  - Then `sin` and `tan` return `x` itself when `tiny(x)`; so do `atan` and `asin` (below).
  - If `tan` as `n / d` misses 0.51 ulp (Step 3), `TAN_INLINE` is `false`, `tanf` is `libm::tan(x as f64) as f32` on every input, and Task 3 leaves `tan` a call.
- **`atan2`:** `(atan_core(|y| as f64, |x| as f64, x.is_sign_negative()) as f32).copysign(y)`.
- **`atan`:** `(atan_core(|x| as f64, 1.0, false) as f32).copysign(x)`, or `x` itself when `tiny(x)`.
- **`asin`:**
  - `let a = |x| as f64; let c = ((1.0 - a) * (1.0 + a)).sqrt();`
  - `(atan_core(a, c, false) as f32).copysign(x)`, or `x` itself when `tiny(x)`.
  - The special path is `asin_special(x)`: `magnitude(x) > 0x3F80_0000`.
- **`acos`:** `atan_core(c, a, x.is_sign_negative()) as f32`, with `c` and `a` as for `asin`. It has no copysign: the result is in `[0, π]`.
- **`fmod`:**
  - `q = trunc(ad / bd)`, then `r = ad - q*bd` and `ab = copysign(|bd|, ad)`.
  - `fix = r != 0 && (r < 0) != (ad < 0)` and `over = !fix && |r| >= |bd|`.
  - `r = fix ? r + ab : over ? r - ab : r`.
  - The result is `r == 0 ? copysign(0f32, a) : r as f32`.

**Interfaces:**

```rust
/// Moves each loop-invariant expression that holds a transcendental `Math` or a float `%` into a
/// new `Value` local bound just before the loop (spec decision 5). Runs per function, outermost
/// loop first; `par for` bodies are functions of their own.
pub fn hoist_math(m: &mut Module);
fn written(stmts: &[Stmt]) -> HashSet<LocalIdx>;   // Let, Bind, BindEnv, BindGlobal, ForRange var, any written place
fn invariant(e: &Expr, written: &HashSet<LocalIdx>, locals: &[Local]) -> bool;
/// The inliner's temporaries the loop body binds to invariant expressions (spec decision 5):
/// local -> initializer, for each `Value` local whose only writes in the loop are `Let`s at the
/// body's top level, each `invariant` by the base rule, before every use, with no use in a
/// `While`'s condition. One level: an initializer that reads another temporary doesn't count.
fn temps(body: &[Stmt], cond: Option<&Expr>, written: &HashSet<LocalIdx>, locals: &[Local]) -> HashMap<LocalIdx, Expr>;
fn costly(e: &Expr) -> bool;                        // holds Math(Sin..=Pow) or a float Binary(Rem)
```

**How the pass works:**
- A `VisitMut` overrides `visit_stmts`. For each `While` or `ForRange` at index `i`, it computes `written` for the loop: the body; for `While`, the condition too; for `ForRange`, the loop variable.
- In the body (and a `While`'s condition), including nested statement lists in `If`, `Seq`, `Assume`, `Prove` and inner loops, it replaces each **maximal** subexpression that is `invariant` and `costly` with `Load` of a fresh local `__hoisted` (`LocalKind::Value`, the expression's type).
- It inserts the `Let`s before index `i`, in the order found. Then it walks into the body, so a loop nested inside gets its own pass.
- `invariant` allows exactly what spec decision 5 lists:
  - `Float`, `Int`, `Bool`;
  - a `Load` of a place with an empty path whose root is a `Value` local not in `written`, or one in `temps` (the hoisted copy gets the initializer in its place; the `Let` in the loop stays);
  - a `Cast` whose type is `F32` or `F64`;
  - `Unary(Neg)` and `Binary(Add | Sub | Mul | Div | Rem)` of float type;
  - `Math` of scalar float type.
- Everything else is not invariant: integer arithmetic, a `Proven`, a cast to an integer, calls, places with paths, `RefParam` and `Addressed` locals, vectors.
